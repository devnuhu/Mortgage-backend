============================================================================
FAILURE INDICATORS & RECOVERY
============================================================================

Error: "No active DocumentTypes found!"
Status: FATAL - Migration cannot proceed
Recovery:
  1. Check DocumentTypes_BACKUP table exists and has rows
  2. Run: RESTORE DocumentTypes table from backup or manually add entries
  3. Execute the migration script again

Error during STEP 3 (constraint disabling)
Status: WARNING - Usually means constraints already disabled
Recovery:
  1. Check output for specific constraint names
  2. Continue execution - step recovery logic may handle it
  3. If execution stops, manually run rest of script starting from STEP 4

Error: "Violation of FOREIGN KEY constraint..."
Status: CRITICAL - FK integrity violated
Recovery:
  1. Note which table and constraint in error message
  2. Review TROUBLESHOOTING_CHECKLIST.txt for specific FK
  3. Manually fix the referenced data
  4. Restart migration OR just rerun STEP 5+ if data already partially loaded

Error: "Cannot insert the value NULL into column 'DocumentTypeId'"
Status: CRITICAL - No default DocumentTypeId available
Recovery:
  1. Restore DocumentTypes_BACKUP
  2. Verify MMGTDB2A.DocumentTypes has at least 1 active entry
  3. Rerun migration script starting from STEP 7

Error: "Duplicate key value..." for Users or PMICompanies
Status: CRITICAL - Target already has data
Recovery:
  1. This means STEP 3 (delete) failed silently
  2. Manually delete target data:
	 USE MMGTDB2A;
	 DELETE FROM Users;
	 DELETE FROM PMICompanies;
  3. Rerun migration starting from STEP 4

Error: Constraint re-enable fails on FK_Users_PMICompanies_PMICompanyId or similar
Status: CRITICAL - Data integrity issue
Recovery:
  1. The validation queries in STEP 10 should identify orphaned records
  2. Review output or manually run validation queries
  3. Fix orphaned records before re-enabling constraints
  4. If FK references old company/user IDs that don't exist, update or delete those rows

ROLLBACK IF NEEDED
============================================================================

If something goes wrong after migration:

Option 1: Restore from backup (cleanest)
-----------------------------------------
1. Restore MMGTDB2A database from pre-migration backup
2. No manual cleanup needed

Option 2: Manual cleanup (if no backup)
---------------------------------------
USE MMGTDB2A;

-- Disable constraints on all affected tables
ALTER TABLE Applications NOCHECK CONSTRAINT ALL;
ALTER TABLE ApplicationDocuments NOCHECK CONSTRAINT ALL;
ALTER TABLE ApplicationReviewHistory NOCHECK CONSTRAINT ALL;
ALTER TABLE Users NOCHECK CONSTRAINT ALL;
ALTER TABLE PMICompanies NOCHECK CONSTRAINT ALL;

-- Delete migrated data
DELETE FROM ApplicationDocuments;
DELETE FROM ApplicationReviewHistory;
DELETE FROM Applications;
DELETE FROM Users;
DELETE FROM PMICompanies;

-- Re-enable constraints
ALTER TABLE Applications WITH CHECK CHECK CONSTRAINT ALL;
ALTER TABLE ApplicationDocuments WITH CHECK CHECK CONSTRAINT ALL;
ALTER TABLE ApplicationReviewHistory WITH CHECK CHECK CONSTRAINT ALL;
ALTER TABLE Users WITH CHECK CHECK CONSTRAINT ALL;
ALTER TABLE PMICompanies WITH CHECK CHECK CONSTRAINT ALL;

-- Verify reference data still exists
SELECT COUNT(*) FROM DocumentTypes;
SELECT COUNT(*) FROM EscalationRules;
